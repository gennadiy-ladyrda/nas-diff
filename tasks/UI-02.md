# UI-02

## 1. Задача
- Краткое название: Ревью групп и центр действий
- Цель (что должно измениться в системе): Реализовать интерфейс для просмотра групп дублей, выбора primary и подтверждения batch-действий.
- Ожидаемый результат в 1-2 предложениях: Пользователь проходит полный review workflow: просмотр группы -> решение -> подтверждение действия.

## 2. Scope
- Входит в задачу: Экран exact/similar групп, карточка сравнения, Action Center.
- Не входит в задачу: Расширенная аналитика по архиву.

## 3. Контекст
- Связанные документы/файлы: `docs/specification.md` FR-5/FR-6, `docs/architecture.md`.
- Текущие ограничения окружения (DSM6, Docker, пути NAS и т.д.): Один пользователь, безопасность удаления критична.
- Зависимости/интеграции: DECISION-01, ACT-01 API.

## 4. Требования
- Функциональные требования: Ручной override primary, массовое добавление в batch, подтверждение и мониторинг исполнения.
- Нефункциональные требования (производительность, безопасность, UX): Удобное side-by-side сравнение; четкие предупреждения перед удалением.
- Ограничения по безопасности данных: По умолчанию действие `move_to_trash`; hard delete требует отдельного подтверждения.

## 5. Критерии приемки
1. Группы дублей отображаются с ключевыми метаданными и превью.
2. Решения пользователя корректно сохраняются и попадают в batch.
3. Action Center показывает статус исполнения и ошибки.

## 6. Проверки и тесты
- Какие проверки обязательны: Проверка end-to-end review workflow.
- Какие тесты нужно запустить: UI integration/e2e tests для decisions/actions.
- Что считается успешной валидацией: Полный сценарий review и confirm выполняется без ручных обходов.

## 7. Риски
- Основные риски: Ошибочное массовое выделение и удаление.
- Что делать при отклонении/ошибке: Добавить превью последствий и защитный confirm-step.

## 8. Уровень неопределенности
Оценка `U = (R + T + D + S) / 4`:
- `R` (requirements): 0.08
- `T` (technical): 0.09
- `D` (data/environment): 0.08
- `S` (safety impact): 0.10
- Итог `U`: 0.09

Если `U > 0.1`, перед реализацией нужны уточнения.

## 9. Формат результата
- Какие артефакты ожидаются (код, конфиги, docs): UI pages/components, state-management, e2e tests.
- Какой отчет нужен в финале: запись пользовательского сценария review и статусы batch.
