# CORE-01

## 1. Задача
- Краткое название: Сканер файлов и инкрементальная индексация
- Цель (что должно измениться в системе): Реализовать безопасный файловый обход NAS и обновление индекса `files`/`file_hashes`.
- Ожидаемый результат в 1-2 предложениях: Сканер обрабатывает тысячи файлов, повторный запуск не пересчитывает неизмененные файлы.

## 2. Scope
- Входит в задачу: Обход `scan_roots`, извлечение метаданных/EXIF, определение изменений по mtime/size/inode.
- Не входит в задачу: Построение exact/similar групп.

## 3. Контекст
- Связанные документы/файлы: `docs/architecture.md`, `docs/specification.md`, `database/schema.sql`.
- Текущие ограничения окружения (DSM6, Docker, пути NAS и т.д.): Чтение только из `/nas`; большие архивы (тысячи файлов).
- Зависимости/интеграции: PIL/ExifTool-библиотека, DB-layer.

## 4. Требования
- Функциональные требования: Сканер отмечает `is_present`, обновляет `last_seen_job_id`, фиксирует новые/измененные файлы.
- Нефункциональные требования (производительность, безопасность, UX): Потоковая обработка без роста RAM; лог прогресса.
- Ограничения по безопасности данных: Только операции чтения, без модификации файлов.

## 5. Критерии приемки
1. Полный скан корректно индексирует тестовый архив.
2. Инкрементальный скан пропускает неизмененные файлы.
3. Удаленные из архива файлы отмечаются как `is_present=0`.

## 6. Проверки и тесты
- Какие проверки обязательны: Проверка счетчиков `files_seen/files_indexed`.
- Какие тесты нужно запустить: Unit tests для change detection + integration scan test.
- Что считается успешной валидацией: Повторный скан быстрее полного и консистентен по данным.

## 7. Риски
- Основные риски: Нестабильные метаданные на разных файловых системах.
- Что делать при отклонении/ошибке: Использовать fallback по `size+mtime`, логировать несогласованные случаи.

## 8. Уровень неопределенности
Оценка `U = (R + T + D + S) / 4`:
- `R` (requirements): 0.07
- `T` (technical): 0.09
- `D` (data/environment): 0.10
- `S` (safety impact): 0.04
- Итог `U`: 0.08

Если `U > 0.1`, перед реализацией нужны уточнения.

## 9. Формат результата
- Какие артефакты ожидаются (код, конфиги, docs): scanner module, индексатор, тесты.
- Какой отчет нужен в финале: метрики полного/инкрементального прогона и ограничения.
