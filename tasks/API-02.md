# API-02

## 1. Задача
- Краткое название: Оркестрация scan jobs и статусы
- Цель (что должно измениться в системе): Реализовать API для создания, мониторинга и получения результатов scan jobs.
- Ожидаемый результат в 1-2 предложениях: Пользователь может запускать scan в режимах `exact|similar|both` и видеть прогресс/результаты.

## 2. Scope
- Входит в задачу: `POST /scan/jobs`, `GET /scan/jobs/{id}`, `GET /scan/jobs/{id}/groups`.
- Не входит в задачу: UI-реализация экранов ревью.

## 3. Контекст
- Связанные документы/файлы: `docs/specification.md` (раздел API), `database/schema.sql` (`scan_jobs`, группы).
- Текущие ограничения окружения (DSM6, Docker, пути NAS и т.д.): Фоновые задачи через Redis/RQ.
- Зависимости/интеграции: Worker queue, DB repositories, dedup services.

## 4. Требования
- Функциональные требования: Создание job с валидацией mode/roots; возврат статуса и агрегированных метрик.
- Нефункциональные требования (производительность, безопасность, UX): Идемпотентность повторных запросов; пагинация групп.
- Ограничения по безопасности данных: API не выполняет file actions в рамках этой задачи.

## 5. Критерии приемки
1. Job создается и попадает в очередь воркера.
2. Endpoint статуса возвращает корректный прогресс и финальный state.
3. Список групп доступен после завершения scan.

## 6. Проверки и тесты
- Какие проверки обязательны: Контракт API и очередей.
- Какие тесты нужно запустить: Integration tests scan lifecycle.
- Что считается успешной валидацией: Успешный сценарий `create -> run -> complete -> read groups`.

## 7. Риски
- Основные риски: Race conditions при одновременных scan jobs.
- Что делать при отклонении/ошибке: Ограничить параллелизм и добавить блокировку на shared ресурсы.

## 8. Уровень неопределенности
Оценка `U = (R + T + D + S) / 4`:
- `R` (requirements): 0.06
- `T` (technical): 0.09
- `D` (data/environment): 0.08
- `S` (safety impact): 0.04
- Итог `U`: 0.07

Если `U > 0.1`, перед реализацией нужны уточнения.

## 9. Формат результата
- Какие артефакты ожидаются (код, конфиги, docs): API маршруты, queue интеграция, контрактные тесты.
- Какой отчет нужен в финале: примеры payload/response и результаты интеграционных тестов.
