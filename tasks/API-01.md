# API-01

## 1. Задача
- Краткое название: Health и управление источниками сканирования
- Цель (что должно измениться в системе): Реализовать базовые API для проверки состояния и управления `scan_roots`.
- Ожидаемый результат в 1-2 предложениях: Клиент может проверить состояние системы и настроить каталоги для сканирования.

## 2. Scope
- Входит в задачу: `GET /api/v1/health`, CRUD для `scan_roots`.
- Не входит в задачу: Запуск scan jobs и выдача групп дублей.

## 3. Контекст
- Связанные документы/файлы: `docs/specification.md`, `docs/architecture.md`, `database/schema.sql`.
- Текущие ограничения окружения (DSM6, Docker, пути NAS и т.д.): Один локальный пользователь, NAS пути доступны внутри `/nas`.
- Зависимости/интеграции: DB-layer (`scan_roots`), Redis ping в health.

## 4. Требования
- Функциональные требования: Health отражает status API/DB/Redis; `scan_roots` поддерживает add/list/disable/remove.
- Нефункциональные требования (производительность, безопасность, UX): Валидация абсолютных путей; предсказуемые коды ошибок.
- Ограничения по безопасности данных: Запрет на добавление путей вне разрешенного mount root.

## 5. Критерии приемки
1. Health endpoint возвращает детальный статус зависимостей.
2. CRUD `scan_roots` работает и сохраняет состояние в БД.
3. Невалидные пути отклоняются с понятным сообщением.

## 6. Проверки и тесты
- Какие проверки обязательны: Контрактная проверка HTTP-кодов.
- Какие тесты нужно запустить: API unit/integration tests для health и roots.
- Что считается успешной валидацией: 100% прохождение тестов по endpoint-ам задачи.

## 7. Риски
- Основные риски: Ошибочная нормализация путей и доступ за пределы mount.
- Что делать при отклонении/ошибке: Ввести строгую проверку префикса `/nas` и canonical path.

## 8. Уровень неопределенности
Оценка `U = (R + T + D + S) / 4`:
- `R` (requirements): 0.05
- `T` (technical): 0.07
- `D` (data/environment): 0.08
- `S` (safety impact): 0.06
- Итог `U`: 0.07

Если `U > 0.1`, перед реализацией нужны уточнения.

## 9. Формат результата
- Какие артефакты ожидаются (код, конфиги, docs): API routes, схемы запросов/ответов, тесты.
- Какой отчет нужен в финале: список endpoint-ов и результаты API-тестов.
