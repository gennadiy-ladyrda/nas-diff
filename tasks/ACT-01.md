# ACT-01

## 1. Задача
- Краткое название: Безопасные batch-действия и rollback
- Цель (что должно измениться в системе): Реализовать жизненный цикл `action_batch` с безопасным исполнением и восстановлением.
- Ожидаемый результат в 1-2 предложениях: Пользователь подтверждает batch, файлы перемещаются в корзину, доступен rollback; hard delete только по флагу.

## 2. Scope
- Входит в задачу: `actions` API, worker executor, `file_movements`, rollback.
- Не входит в задачу: Продвинутые политики retention корзины.

## 3. Контекст
- Связанные документы/файлы: `docs/specification.md` FR-6/FR-7, `database/schema.sql` action tables.
- Текущие ограничения окружения (DSM6, Docker, пути NAS и т.д.): Корзина внутри `/nas/.nas-diff-trash`.
- Зависимости/интеграции: user decisions, file system permissions.

## 4. Требования
- Функциональные требования: Поддержка `draft -> confirmed -> executed`; `move_to_trash`, `restore`, `delete_permanent`.
- Нефункциональные требования (производительность, безопасность, UX): Частично неуспешные batch не теряют трассировку; четкие причины ошибок.
- Ограничения по безопасности данных: Hard delete только при `HARD_DELETE_ENABLED=true` и явном подтверждении.

## 5. Критерии приемки
1. Batch move-to-trash выполняется и логируется пофайлово.
2. Rollback возвращает файлы по `file_movements`.
3. Hard delete блокируется при выключенном флаге.

## 6. Проверки и тесты
- Какие проверки обязательны: Проверка статус-машины batch.
- Какие тесты нужно запустить: Integration tests for execute/rollback/failure path.
- Что считается успешной валидацией: Никаких silent-fail, все ошибки отражены в `action_items`.

## 7. Риски
- Основные риски: Потеря файла при конфликте пути назначения.
- Что делать при отклонении/ошибке: Предварительная проверка target path и rollback step-by-step.

## 8. Уровень неопределенности
Оценка `U = (R + T + D + S) / 4`:
- `R` (requirements): 0.06
- `T` (technical): 0.09
- `D` (data/environment): 0.09
- `S` (safety impact): 0.10
- Итог `U`: 0.09

Если `U > 0.1`, перед реализацией нужны уточнения.

## 9. Формат результата
- Какие артефакты ожидаются (код, конфиги, docs): action API, executor worker, rollback logic, тесты.
- Какой отчет нужен в финале: статистика batch execution + примеры rollback.
