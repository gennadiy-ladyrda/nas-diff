# INFRA-01

## 1. Задача
- Краткое название: Базовый каркас backend/worker и контейнеров
- Цель (что должно измениться в системе): Подготовить исполняемую базу проекта с сервисами `api`, `worker`, `redis` и минимальным Python-каркасом backend.
- Ожидаемый результат в 1-2 предложениях: Проект стартует через Docker на DSM6, есть рабочий health endpoint и воркер-процесс.

## 2. Scope
- Входит в задачу: `backend/Dockerfile`, `requirements`, структура `app/`, entrypoints для API и worker, согласование с `docker-compose.yml`.
- Не входит в задачу: Реализация алгоритмов дедупликации и полнофункциональный UI.

## 3. Контекст
- Связанные документы/файлы: `docs/blueprint-v1.md`, `docs/specification.md`, `docker-compose.yml`.
- Текущие ограничения окружения (DSM6, Docker, пути NAS и т.д.): DSM6 x86, Docker, доступ к NAS через volume `/volume1 -> /nas`.
- Зависимости/интеграции: Redis для очередей, SQLite файл в `/data`.

## 4. Требования
- Функциональные требования: API поднимается на `:8080`; worker запускается отдельным процессом; конфигурация читается из env.
- Нефункциональные требования (производительность, безопасность, UX): Холодный старт контейнеров без ручных действий; единый образ для API/worker.
- Ограничения по безопасности данных: Никаких операций удаления файлов в этой задаче.

## 5. Критерии приемки
1. `docker compose up -d` поднимает все сервисы без ошибок.
2. `GET /api/v1/health` возвращает `200`.
3. Логи worker подтверждают успешный старт цикла обработки задач.

## 6. Проверки и тесты
- Какие проверки обязательны: `docker compose config`, smoke-check контейнеров.
- Какие тесты нужно запустить: Минимальный API smoke test.
- Что считается успешной валидацией: Стабильный запуск и доступность health.

## 7. Риски
- Основные риски: Несовместимость зависимостей Python с DSM6 base image.
- Что делать при отклонении/ошибке: Зафиксировать версии пакетов и перейти на совместимый slim-base.

## 8. Уровень неопределенности
Оценка `U = (R + T + D + S) / 4`:
- `R` (requirements): 0.05
- `T` (technical): 0.08
- `D` (data/environment): 0.08
- `S` (safety impact): 0.02
- Итог `U`: 0.06

Если `U > 0.1`, перед реализацией нужны уточнения.

## 9. Формат результата
- Какие артефакты ожидаются (код, конфиги, docs): Dockerfile, backend scaffold, обновленные конфиги.
- Какой отчет нужен в финале: список файлов, команды проверки, статус старта сервисов.
