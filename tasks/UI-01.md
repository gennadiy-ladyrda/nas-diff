# UI-01

## 1. Задача
- Краткое название: Dashboard и экран запуска сканирования
- Цель (что должно измениться в системе): Реализовать базовый интерфейс запуска scan и отображения статусов/метрик.
- Ожидаемый результат в 1-2 предложениях: Пользователь может выбрать режим и пути, запустить scan и видеть прогресс в реальном времени.

## 2. Scope
- Входит в задачу: Страницы `Dashboard` и `Scan Setup`, интеграция с API health/scan jobs.
- Не входит в задачу: Экран детального ревью групп.

## 3. Контекст
- Связанные документы/файлы: `docs/specification.md` UI/API разделы, `docs/architecture.md`.
- Текущие ограничения окружения (DSM6, Docker, пути NAS и т.д.): Один локальный пользователь, LAN-only.
- Зависимости/интеграции: API-01/API-02 endpoints.

## 4. Требования
- Функциональные требования: Выбор режима `exact|similar|both`, запуск job, просмотр статуса и итоговых метрик.
- Нефункциональные требования (производительность, безопасность, UX): Простая и понятная навигация; адаптивность desktop/tablet.
- Ограничения по безопасности данных: UI не предлагает hard delete как действие по умолчанию.

## 5. Критерии приемки
1. Scan можно запустить из UI с валидными параметрами.
2. Прогресс job и финальные метрики отображаются корректно.
3. Ошибки API отображаются пользователю без потери контекста.

## 6. Проверки и тесты
- Какие проверки обязательны: Проверка контрактов UI->API.
- Какие тесты нужно запустить: Component tests + e2e smoke для запуска scan.
- Что считается успешной валидацией: Пользовательский сценарий запуска scan проходит end-to-end.

## 7. Риски
- Основные риски: Неконсистентные статусы при долгих задачах.
- Что делать при отклонении/ошибке: Polling с backoff и повторная синхронизация состояния.

## 8. Уровень неопределенности
Оценка `U = (R + T + D + S) / 4`:
- `R` (requirements): 0.07
- `T` (technical): 0.08
- `D` (data/environment): 0.07
- `S` (safety impact): 0.04
- Итог `U`: 0.07

Если `U > 0.1`, перед реализацией нужны уточнения.

## 9. Формат результата
- Какие артефакты ожидаются (код, конфиги, docs): React pages/components, API client, UI tests.
- Какой отчет нужен в финале: скрин-путь сценария и результаты UI smoke/e2e.
