# UI-03

## 1. Задача
- Краткое название: Dashboard layout и управление scan roots
- Цель (что должно измениться в системе): Улучшить UX dashboard: компактный вертикальный блок `System Health` и безопасное удаление root-каталогов.
- Ожидаемый результат в 1-2 предложениях: Health отображается компактно слева, оператор может удалять ошибочные/ненужные roots прямо из UI.

## 2. Scope
- Входит в задачу: Редизайн `Dashboard` layout, UI-кнопка удаления roots, confirm-step, отображение ошибок API.
- Не входит в задачу: Полный редизайн `Review & Actions`.

## 3. Контекст
- Связанные документы/файлы: `frontend/src/pages/DashboardPage.jsx`, `docs/specification.md`.
- Текущие ограничения окружения (DSM6, Docker, пути NAS и т.д.): desktop-first + tablet адаптивность.
- Зависимости/интеграции: API-01 (scan roots CRUD), API-03 (при необходимости дополнительной валидации).

## 4. Требования
- Функциональные требования:
  - `System Health` сделать компактным, вертикальным, закрепленным слева в desktop layout.
  - Для каждого root добавить `Delete` в UI с явным confirm.
  - При `409/422` отображать человеку понятную причину отказа.
- Нефункциональные требования (производительность, безопасность, UX): Управление roots не ломает текущий запуск scan.
- Ограничения по безопасности данных: Удаляются только записи roots, не файлы NAS.

## 5. Критерии приемки
1. Dashboard визуально разделен: Health слева, рабочий контент справа.
2. Root можно удалить из UI в happy-path.
3. Ошибочные удаления возвращают понятное сообщение без потери контекста.

## 6. Проверки и тесты
- Какие проверки обязательны: UI contract tests для delete root.
- Какие тесты нужно запустить: Component tests dashboard + API smoke roots.
- Что считается успешной валидацией: Сценарий add/delete root воспроизводим и стабилен.

## 7. Риски
- Основные риски: Пользователь случайно удаляет root перед scan.
- Что делать при отклонении/ошибке: Confirm + мягкие предупреждения + возможность быстро добавить root обратно.

## 8. Уровень неопределенности
Оценка `U = (R + T + D + S) / 4`:
- `R` (requirements): 0.07
- `T` (technical): 0.07
- `D` (data/environment): 0.06
- `S` (safety impact): 0.06
- Итог `U`: 0.07

Если `U > 0.1`, перед реализацией нужны уточнения.

## 9. Формат результата
- Какие артефакты ожидаются (код, конфиги, docs): Обновленные UI-компоненты dashboard + тесты.
- Какой отчет нужен в финале: Скрин/описание layout изменений и результаты UI тестов.
