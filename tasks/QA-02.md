# QA-02

## 1. Задача
- Краткое название: Регрессия для roots/jobs/bulk UX
- Цель (что должно измениться в системе): Закрыть тестами новый функционал по roots, jobs table/delete и групповым операциям.
- Ожидаемый результат в 1-2 предложениях: Изменения `API-03 + UI-03 + UI-04 + ACT-02` покрыты стабильными автотестами и e2e smoke.

## 2. Scope
- Входит в задачу: API tests, service/integration tests, UI component tests, e2e smoke сквозного сценария.
- Не входит в задачу: Нагрузочные тесты production-масштаба.

## 3. Контекст
- Связанные документы/файлы: `scripts/ci/run_s3_regression_suite.sh`, `backend/tests/`, `frontend/tests/`, `docs/specification.md`.
- Текущие ограничения окружения (DSM6, Docker, пути NAS и т.д.): Тесты должны быть воспроизводимыми локально.
- Зависимости/интеграции: API-03, UI-03, UI-04, ACT-02.

## 4. Требования
- Функциональные требования:
  - API: list/delete jobs, delete roots conflict cases.
  - UI: dashboard layout, jobs table/detail-row, root delete flow.
  - Bulk actions: preview/confirm/execute/rollback сценарии.
- Нефункциональные требования (производительность, безопасность, UX): Минимум flaky-тестов, deterministic fixtures.
- Ограничения по безопасности данных: Тесты работают на изолированных test-datasets.

## 5. Критерии приемки
1. Полный набор новых сценариев запускается одной командой.
2. Критические user-flows имеют автоматическую проверку.
3. Сквозной e2e smoke стабильно зеленый.

## 6. Проверки и тесты
- Какие проверки обязательны: `pytest`, `vitest`, `playwright`.
- Какие тесты нужно запустить: Полный regression suite (`scripts/ci/run_s3_regression_suite.sh`).
- Что считается успешной валидацией: Зеленый прогон без ручных обходов.

## 7. Риски
- Основные риски: flakiness из-за async polling и фоновых очередей.
- Что делать при отклонении/ошибке: Повысить детерминированность моков/фикстур и стабилизировать тайминги.

## 8. Уровень неопределенности
Оценка `U = (R + T + D + S) / 4`:
- `R` (requirements): 0.06
- `T` (technical): 0.08
- `D` (data/environment): 0.08
- `S` (safety impact): 0.04
- Итог `U`: 0.07

Если `U > 0.1`, перед реализацией нужны уточнения.

## 9. Формат результата
- Какие артефакты ожидаются (код, конфиги, docs): новые тестовые модули/фикстуры и обновленный CI regression.
- Какой отчет нужен в финале: результаты полного прогона и список покрытых сценариев.
