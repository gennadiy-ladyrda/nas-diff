# OPS-01

## 1. Задача
- Краткое название: Эксплуатация и runbook для DSM6
- Цель (что должно измениться в системе): Подготовить эксплуатационную документацию для установки, обновления, бэкапа и восстановления.
- Ожидаемый результат в 1-2 предложениях: Оператор может развернуть и сопровождать систему на DSM6 без дополнительного устного контекста.

## 2. Scope
- Входит в задачу: Install guide, env-конфигурация, backup/restore SQLite и Redis, troubleshooting.
- Не входит в задачу: Автоматизация CI/CD.

## 3. Контекст
- Связанные документы/файлы: `docker-compose.yml`, `.env.example`, `docs/architecture.md`, `docs/specification.md`.
- Текущие ограничения окружения (DSM6, Docker, пути NAS и т.д.): Локальный deployment в LAN, данные на томах NAS.
- Зависимости/интеграции: Docker Compose, Container Manager DSM6.

## 4. Требования
- Функциональные требования: Пошаговые инструкции install/start/stop/update/backup/restore.
- Нефункциональные требования (производительность, безопасность, UX): Документация краткая, но достаточная для повторяемого запуска.
- Ограничения по безопасности данных: Отдельно выделить safe defaults и правила работы с `delete_permanent`.

## 5. Критерии приемки
1. По инструкции проект разворачивается с нуля.
2. Описан и проверен сценарий backup+restore индекса.
3. Раздел troubleshooting покрывает типовые сбои (DB lock, Redis down, permission denied).

## 6. Проверки и тесты
- Какие проверки обязательны: Dry-run по инструкции на чистом окружении.
- Какие тесты нужно запустить: Smoke start/stop, backup/restore check.
- Что считается успешной валидацией: Повторяемый deployment по документации.

## 7. Риски
- Основные риски: Неполные инструкции по правам доступа к NAS-папкам.
- Что делать при отклонении/ошибке: Добавить отдельный раздел валидации прав и ownership.

## 8. Уровень неопределенности
Оценка `U = (R + T + D + S) / 4`:
- `R` (requirements): 0.05
- `T` (technical): 0.07
- `D` (data/environment): 0.09
- `S` (safety impact): 0.07
- Итог `U`: 0.07

Если `U > 0.1`, перед реализацией нужны уточнения.

## 9. Формат результата
- Какие артефакты ожидаются (код, конфиги, docs): runbook в `docs/ops/`, команды обслуживания, чеклисты.
- Какой отчет нужен в финале: подтверждение прохождения dry-run по инструкции.
