# UI-06

## 1. Задача
- Краткое название: Hamburger-навигация и старт приложения с Simple Scan
- Цель (что должно измениться в системе): Свернуть навигацию `Advanced` и `Review & Actions` в menu-"бутерброд" и сделать `Simple Scan` стартовым экраном по умолчанию.
- Ожидаемый результат в 1-2 предложениях: При открытии приложения пользователь попадает на `Simple Scan`, а доступ к `Advanced` и `Review & Actions` осуществляется через компактное hamburger-меню.

## 2. Scope
- Входит в задачу: Новый topbar navigation pattern, изменение default route, mobile/desktop адаптация menu.
- Не входит в задачу: Удаление advanced/review экранов из продукта.

## 3. Контекст
- Связанные документы/файлы: `frontend/src/App.jsx`, `frontend/src/styles/global.css`, `frontend/src/pages/DashboardPage.jsx`.
- Текущие ограничения окружения (DSM6, Docker, пути NAS и т.д.): Работа в локальной сети, desktop-first UX с корректной мобильной деградацией.
- Зависимости/интеграции: UI-05 (Simple Scan как primary flow).

## 4. Требования
- Функциональные требования:
  - Маршрут по умолчанию (`/`) должен открывать `Simple Scan`.
  - `Advanced` и `Review & Actions` доступны через hamburger-меню.
  - Меню должно поддерживать открытие/закрытие, текущий активный маршрут, закрытие по клику вне области/по Esc.
  - Прямые ссылки на `Advanced` и `Review` должны оставаться рабочими.
- Нефункциональные требования (производительность, безопасность, UX): Навигация должна быть предсказуемой и доступной (keyboard + ARIA).
- Ограничения по безопасности данных: Только UI-навигация, без операций над файлами.

## 5. Критерии приемки
1. `Simple Scan` открывается по умолчанию при заходе в приложение.
2. `Advanced` и `Review & Actions` скрыты из постоянной topbar-навигации и доступны через hamburger.
3. Меню корректно работает на desktop и mobile, включая keyboard navigation.

## 6. Проверки и тесты
- Какие проверки обязательны: Component tests для nav/menu состояния и route switching.
- Какие тесты нужно запустить: `vitest` по `App`/navigation + e2e smoke маршрутизации.
- Что считается успешной валидацией: Корректный default route и стабильная навигация через hamburger.

## 7. Риски
- Основные риски: Потеря discoverability advanced/review функций.
- Что делать при отклонении/ошибке: Добавить понятный label/tooltip в меню и сохранить прямые deep-link маршруты.

- Итог `U`: 0.06

## 9. Формат результата
- Какие артефакты ожидаются (код, конфиги, docs): Обновленные `App` routing/navigation + CSS + tests + notes в `docs/specification.md`.
