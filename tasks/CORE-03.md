# CORE-03

## 1. Задача
- Краткое название: Similar режим (похожие фото)
- Цель (что должно измениться в системе): Реализовать поиск похожих фото на основе perceptual hashing.
- Ожидаемый результат в 1-2 предложениях: Система формирует кластеры похожих изображений по настраиваемому порогу Hamming distance.

## 2. Scope
- Входит в задачу: Вычисление `dhash64/phash64`, построение графа похожести, формирование `similar_groups`.
- Не входит в задачу: UX-полировка UI сравнения и массовых операций.

## 3. Контекст
- Связанные документы/файлы: `docs/specification.md` FR-4, `docs/architecture.md`, `database/schema.sql`.
- Текущие ограничения окружения (DSM6, Docker, пути NAS и т.д.): Порог похожести должен конфигурироваться через env/API.
- Зависимости/интеграции: image-processing библиотека, scanner metadata.

## 4. Требования
- Функциональные требования: Similar-группы поддерживают `threshold`, `distance_to_anchor`, `confidence`.
- Нефункциональные требования (производительность, безопасность, UX): Адекватное время обработки для тысяч фото; возможность пересчета при смене порога.
- Ограничения по безопасности данных: Без изменений исходных файлов.

## 5. Критерии приемки
1. Похожие фото из контрольного датасета группируются корректно.
2. Изменение порога влияет на результат предсказуемо.
3. Группы и дистанции сохраняются в БД.

## 6. Проверки и тесты
- Какие проверки обязательны: Валидация Hamming distance и cluster assembly.
- Какие тесты нужно запустить: Unit tests hashing distance + integration test similar mode.
- Что считается успешной валидацией: При фиксированном датасете результат стабилен между запусками.

## 7. Риски
- Основные риски: Ложные срабатывания на однотонных/низкоконтрастных фото.
- Что делать при отклонении/ошибке: Добавить hybrid-score и ручную валидацию в UI.

## 8. Уровень неопределенности
Оценка `U = (R + T + D + S) / 4`:
- `R` (requirements): 0.08
- `T` (technical): 0.10
- `D` (data/environment): 0.10
- `S` (safety impact): 0.04
- Итог `U`: 0.08

Если `U > 0.1`, перед реализацией нужны уточнения.

## 9. Формат результата
- Какие артефакты ожидаются (код, конфиги, docs): similar dedup модули, настройки порога, тесты.
- Какой отчет нужен в финале: precision/recall на контрольном наборе и рекомендации по порогу.
