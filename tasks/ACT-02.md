# ACT-02

## 1. Задача
- Краткое название: Групповые операции над файлами (safe-by-default)
- Цель (что должно измениться в системе): Добавить безопасные массовые операции по выбранным файлам/группам с preview последствий.
- Ожидаемый результат в 1-2 предложениях: Оператор может выполнять batch-действия над большим набором файлов с прозрачным подтверждением и контролем рисков.

## 2. Scope
- Входит в задачу: Модель массового выбора, preview последствий, усиленный confirm для destructive режимов, мониторинг partial failures.
- Не входит в задачу: Полная автоматизация policy-движка по всем группам архива.

## 3. Контекст
- Связанные документы/файлы: `docs/specification.md` FR-6/NFR-2, `backend/app/services/action_service.py`, `frontend/src/pages/ReviewPage.jsx`.
- Текущие ограничения окружения (DSM6, Docker, пути NAS и т.д.): Один пользователь, критична безопасность удаления.
- Зависимости/интеграции: DECISION-01, ACT-01, UI-04.

## 4. Требования
- Функциональные требования:
  - Массовый выбор: `selected`, `all in group`, `all filtered`.
  - Preview: количество файлов, суммарный объем, тип действия.
  - Confirm-step: отдельный усиленный сценарий для `delete_permanent`.
  - После исполнения: явный отчет по done/failed/skipped + быстрый rollback для `move_to_trash`.
- Нефункциональные требования (производительность, безопасность, UX): Предсказуемые операции без silent-fail и случайных destructive действий.
- Ограничения по безопасности данных: По умолчанию только `move_to_trash`; hard delete только при явном флаге и подтверждении.

## 5. Критерии приемки
1. Массовые batch-операции доступны и понятны пользователю.
2. Preview последствий обязателен перед confirm.
3. Частичные ошибки прозрачно отражаются, rollback доступен для восстановимых операций.

## 6. Проверки и тесты
- Какие проверки обязательны: Integration tests на bulk workflow + rollback.
- Какие тесты нужно запустить: API/Service tests + UI integration/e2e.
- Что считается успешной валидацией: Массовый сценарий проходит без потери контроля и данных.

## 7. Риски
- Основные риски: Ошибочный массовый выбор и удаление.
- Что делать при отклонении/ошибке: Preview + staged confirm + ограничение destructive по умолчанию.

## 8. Уровень неопределенности
Оценка `U = (R + T + D + S) / 4`:
- `R` (requirements): 0.09
- `T` (technical): 0.10
- `D` (data/environment): 0.08
- `S` (safety impact): 0.10
- Итог `U`: 0.09

Если `U > 0.1`, перед реализацией нужны уточнения.

## 9. Формат результата
- Какие артефакты ожидаются (код, конфиги, docs): API/service/UI changes + тесты + обновление user flow docs.
- Какой отчет нужен в финале: Демонстрация bulk-flow с preview/confirm/rollback и результаты автотестов.
