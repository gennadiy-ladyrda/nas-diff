# Архитектура NAS Diff

## 1. Контекст
Приложение работает в Docker-контейнерах на Synology DSM6, сканирует локальные тома NAS и формирует группы дублей фотографий. Система рассчитана на одного пользователя в локальной сети.

## 2. Логическая схема компонентов
1. `Web UI`
- Настройка скана (Exact/Similar)
- Просмотр групп
- Подтверждение действий (корзина/удаление)

2. `API Backend (FastAPI)`
- Управление сканами и статусами
- Предоставление данных по группам дублей
- Формирование action batch

3. `Worker (RQ)`
- Файловый обход
- Хэширование
- Построение exact/similar групп
- Выполнение подтвержденных действий

4. `SQLite`
- Индекс файлов
- Хэши
- Группы дублей
- Решения пользователя и журнал операций

5. `Redis`
- Очередь фоновых задач
- Буферизация статусов выполнения

## 3. Потоки данных
### 3.1 Сканирование
1. Пользователь запускает `POST /scan/jobs`.
2. API создает запись `scan_jobs` со статусом `queued`.
3. Worker читает `scan_roots`, обходит файловую систему NAS.
4. Для каждого файла:
- обновляет метаданные в `files`
- считает `blake3_full` (Exact)
- считает `dhash64/phash64` (Similar)
5. После обхода worker собирает группы:
- `exact_groups` + `exact_group_items`
- `similar_groups` + `similar_group_items`
6. API обновляет итоговые метрики: найденные группы, потенциальная экономия.

### 3.2 Ревью и действие
1. UI показывает группу и предложенный `primary` файл.
2. Пользователь корректирует выбор и создает `action_batch` (`draft`).
3. После подтверждения batch переходит в `confirmed`.
4. Worker исполняет batch:
- `move_to_trash` по умолчанию
- `delete_permanent` только при явном подтверждении
5. Результат фиксируется в `action_items` и `file_movements`.

## 4. Алгоритмы
### 4.1 Exact Mode
- Кандидаты: группировка по `size_bytes`.
- Подтверждение: `blake3_full`.
- Группа дубликатов создается при `count >= 2`.

### 4.2 Similar Mode
- Вычисляется `dhash64` и/или `phash64`.
- Сходство: расстояние Хэмминга.
- Порог по умолчанию: `<= 8` (настраиваемый).
- Кластеры строятся поверх графа похожести (connected components).

### 4.3 Выбор primary
Базовый скоринг:
- выше `width * height`
- больше `size_bytes`
- есть `EXIF datetime_original`
- новее по `mtime` (как tie-breaker)

## 5. Безопасность и надежность
- По умолчанию `HARD_DELETE_ENABLED=false`.
- Все действия выполняются только через подтвержденный `action_batch`.
- Для перемещений ведется `file_movements`, что дает восстановление.
- Файлы не затрагиваются во время скана (только чтение), кроме этапа исполнителя действий.

## 6. Нефункциональные требования
- Производительность: тысячи файлов и единицы ТБ должны обрабатываться без исчерпания RAM.
- Инкрементальность: повторный скан переиспользует данные неизмененных файлов.
- Наблюдаемость: логи по job/batch, метрики прогресса.
- Восстанавливаемость: сохранение состояния в SQLite + Redis AOF.

## 7. Ограничения v1
- Один пользователь, без ролевой модели.
- Без распознавания содержимого (лица/объекты) - только хэши и метаданные.
- Без кросс-NAS кластера, только локальный инстанс.
