# Startup Context Pack

Документ для быстрого восстановления проектного контекста в новом чате.

## 1. Продукт и цель
`nas-diff` — приложение для поиска дубликатов фото на Synology NAS.

Бизнес-цель:
- уменьшить занятое место в семейном фотоархиве,
- сделать удаление безопасным и контролируемым.

## 2. Подтвержденные вводные
- Платформа: Synology NAS, `x86`, `DSM6`.
- Формат поставки: `Docker`.
- Режимы поиска: `Exact` и `Similar`.
- Масштаб: тысячи файлов, единицы терабайт.
- Политика удаления:
  - по умолчанию перенос в корзину/карантин,
  - физическое удаление только после подтверждения.
- Пользователь: один пользователь в локальной сети.

## 3. Технический baseline (v1)
- Backend: `Python 3.11 + FastAPI`.
- Фоновые задачи: `RQ + Redis`.
- БД: `SQLite`.
- Контейнеры: `api`, `worker`, `redis`.

Текущие ключевые файлы:
- `docker-compose.yml`
- `.env.example`
- `database/schema.sql`
- `docs/architecture.md`
- `docs/specification.md`
- `docs/blueprint-v1.md`

## 4. Архитектурные принципы
1. Safety-first:
- по умолчанию без необратимых действий,
- batch-подтверждение перед исполнением.

2. Инкрементальность:
- повторные сканы переиспользуют существующий индекс.

3. Наблюдаемость:
- статус сканов и действий должен быть виден через API/UI.

4. Простота эксплуатации:
- локальный single-node инстанс,
- без внешних зависимостей, кроме Redis.

## 5. Что считать успешной поставкой
- Корректная индексация и группировка exact/similar дублей.
- Удобный review групп перед действием.
- Надежный workflow `draft -> confirm -> execute`.
- Возможность rollback для перемещенных файлов.

## 6. Вне рамок v1
- Многопользовательская авторизация.
- Распознавание лиц/сцен и ML-классификация.
- Распределенная обработка между несколькими NAS.

## 7. Быстрый чек перед стартом новой задачи
1. Определить тип задачи: архитектура / backend / worker / UI / data.
2. Проверить, затрагивает ли задача безопасность файлов.
3. Выбрать минимальный набор файлов для загрузки контекста.
4. Оценить неопределенность (цель: `U <= 0.1`).
